# Проект: Аудит и усиление безопасности компании «ИнвестПро»

## Описание проекта

В рамках курса Яндекс.Практикум я провел полный цикл аудита и усиления информационной безопасности компании «ИнвестПро». Проект включает анализ текущих угроз, моделирование рисков и практическую реализацию защитных мер.

Цель проекта: Обеспечить комплексную защиту инфраструктуры компании: от харденинга ОС до сегментации сети и настройки WAF.

## Стек технологий

- Операционные системы: Ubuntu 22.04
- Сетевые технологии: nftables, VLAN, сегментация сети
- Сервисы и службы: Nginx, Postfix, Dovecot, Samba, BIND9, TrueConf
- Средства защиты: BunkerWeb (WAF), ClamAV, Rspamd, ModSecurity
- Инструменты анализа: Nmap, Docker, Git

---

## Реализованные задачи

### 1. Харденинг операционных систем

#### Минимальные привилегии для пользователей
- Действие: Пользователь boss исключен из группы sudo.
- Результат: Теперь у директора по инвестициям только ограниченный набор разрешенных команд (например, перезапуск accounting-software), доступ к root запрещен.
- Почему это важно: Минимизация риска при компрометации учетной записи высокопоставленного сотрудника.

#### Настройка парольной политики
- Действие: Установлена политика сложности паролей (минимум 12 символов, цифры, спецсимволы, запрет повторяющихся символов), срок действия паролей — 90 дней.
- Результат: Снижение риска подбора паролей методом перебора.

#### Изменение пароля директора
- Новый пароль: InvestPro@Secure2024!
- Результат: Замена стандартного пароля на сложный, соответствующий новой политике.

---

### 2. Защита веб-сервера

#### Перенаправление трафика через WAF
- Действие: Весь трафик к веб-серверу перенаправлен через WAF BunkerWeb.
- Результат: Сайт investpro.local доступен, несуществующие пути блокируются с кодом 403.
- Схема: Интернет → FW (DNAT) → WAF → Веб-сервер

#### Настройка WAF
- Действие: В BunkerWeb активированы правила:
  - Защита от сканирования (скрытые директории: /.git/, /admin, /backup).
  - Блокировка подозрительных User-Agent.
  - Защита от DDoS.
- Результат: Успешный тест доступа к /.env возвращает HTTP 403 Forbidden.

#### Харденинг Nginx
- Действие: Запрет доступа к логам веб-сервера через ModSecurity правило.
- Результат: Запрос к /log/ блокируется. Логи защищены от внешнего доступа.

---

### 3. Защита электронной почты

#### Настройка почтового сервера
- Действие:
  - Отключены опасные команды (VRFY, EXPN).
  - Включена проверка HELO, ограничения на подключения.
  - Настроены шифрование и аутентификация (DKIM/SPF/DMARC).
- Результат: Снижение риска спам-атак и сбора адресов.

#### Антиспам-фильтрация
- Действие: Внедрен Rspamd с весовыми правилами и грейлистингом.
- Результат: Успешная фильтрация тестовых фишинговых писем.

---

### 4. Защита файловых ресурсов

#### Разграничение доступа
- Действие: Настроена Samba с группами доступа и ACL.
- Результат: Доступ к каталогам строго по ролям:

| Роль | Каталог | Доступ |
|------|---------|--------|
| Директор (boss) | finance, hr, clients, backup | Полный доступ |
| Бухгалтер (accountant) | finance, clients | Чтение/запись |
| Сотрудники (all_users) | common | Чтение/запись |
| Администраторы (admin) | it | Полный доступ |

#### Безопасность Samba
- Действие: Обязательное шифрование SMB3, отключен анонимный доступ.
- Результат: Защита данных от перехвата.

---

### 5. Защита от вирусов

#### Установка ClamAV
- Действие: ClamAV установлен и обновлен на всех ключевых компьютерах (администратор, директор, файловый сервер).
- Результат: Успешное детектирование тестового файла EICAR.

---

### 6. Фильтрация трафика и сегментация сети

#### Новая архитектура сети
- Действие: Внедрена сегментация сети с выделением зон:
  - LAN (пользователи)
  - SERVERS (внутренние серверы)
  - DMZ (публичные сервисы)
  - MGMT (управление)
  - WAF (прокси)

#### Правила nftables
- Действие: Разработаны и применены правила фильтрации на основе модели угроз и принципа минимальных привилегий.
- Результат:
  - Из интернета доступны только порты 80 и 443 (через WAF).
  - SSH к серверам разрешен только из сегмента управления.
  - Все лишние порты скрыты (вместо REJECT используется DROP, затрудняя сканирование).

---

### 7. Проверка работоспособности

#### Доступность из интернета (сканирование)
- Результат: Видны только порты 80 и 443.
- Вывод: Административные интерфейсы надежно скрыты.

#### Доступность внутри сети
- С компьютера администратора: SSH работает к серверам во всех сегментах.
- С компьютера директора: Доступ есть только к бизнес-сервисам (почта, веб, файловый), SSH к другим сегментам заблокирован.
- Вывод: Принцип минимальных привилегий соблюден на уровне сети.
